## 1. N — Need：用户需求

大学生在日常学习中通常需要同时处理课程安排、作业任务、考试提醒以及课程笔记等多种信息。目前这些信息往往分散在不同的平台中，例如课表 App、备忘录、Todo 软件以及课程群聊等，存在以下问题：

1. **课程信息与任务信息相互割裂**  
    学生虽然可以通过课表查看课程时间，但课程对应的作业、实验、考试等任务通常需要在其他软件中单独记录，难以形成统一的课程管理体系。
    
2. **课程相关信息缺乏关联**  
    某一门课程可能同时包含课程时间、教师信息、作业、考试、笔记和临时提醒等内容，但传统工具通常只能解决其中某一类问题。
    
3. **信息记录流程繁琐**  
    当教师在课堂上布置任务时，用户往往需要退出课表，再打开 Todo 或备忘录进行记录，操作路径较长。
    
4. **不同学期的课程管理不够方便**  
    用户需要保存和管理不同学期的课程，并能够快速切换当前学期、查看历史课程。
    

因此，ClassFlow 希望提供一个围绕“课程”组织学习信息的统一平台，使课程、任务与笔记之间能够自然关联。

---

## 2. A — Approach：解决方案

ClassFlow 是一款面向大学生的课程管理与学习规划应用，以**课程表作为核心入口**，将课程、任务和课程笔记进行整合。

### 2.1 课程表管理

用户可以创建并管理自己的学期课表，并通过清晰的时间视图查看课程安排。

系统支持课程基本信息管理，包括：

- 课程名称
    
- 上课时间
    
- 上课地点
    
- 任课教师
    
- 课程颜色或分类
    
- 所属学期
    

同时支持学期管理，使用户可以切换当前学期以及查看历史课程。

### 2.2 课程与 Todo 联动

ClassFlow 不仅展示课程时间，还允许用户直接在课程页面中创建与该课程相关的任务。

例如：

> 软件工程 —— 完成需求分析报告 —— 周五截止

任务会自动与对应课程建立关联，用户既可以从课程详情中查看，也可以在统一的任务列表中管理。

### 2.3 课程笔记与备忘

用户可以为某一门课程添加简单的笔记或备忘内容，例如：

- 下节课需要携带的材料
    
- 教师临时通知
    
- 实验要求
    
- 考试重点
    
- 课堂临时记录
    

通过课程与笔记之间的关联，减少信息分散的问题。

### 2.4 多层级信息组织

ClassFlow 将学习信息组织为：

```
学期
└── 课程
    ├── 任务
    └── 笔记
```

相比将课程、任务和笔记分别保存在不同软件中的方式，这种组织结构为每条学习信息提供了明确的课程归属。用户可以从某一门课程出发，集中查看相关任务与记录；也可以从统一任务列表出发，了解不同课程的待办事项。

这种方式兼顾了两类使用需求：**按课程查找信息**与**跨课程安排任务**。学期则作为上层管理单位，帮助用户区分当前学习内容和历史记录，减少不同学期、同名课程之间的混淆。

### 2.5 多视图与课节作息适配

原型提供日、周、月三种课表视图，分别支持查看当天安排、一周分布和整月概况。月视图还展示选定日期的课程与到期待办，帮助用户将上课安排与任务截止日期放在同一时间背景下理解。

在日、周视图中，用户可选择按“时间”或“课节”查看课程。按课节安排的课程跟随本学期的作息时间表；自定时间的安排则不随课节时间修改。具体时间尚未配置时，仍保留课节视图，并引导用户补充作息时间，避免必须先完成全部设置才能查看课程。

### 2.6 课表导入与冲突处理

原型设计了文件导入、图片导入和手动录入三种入口，并展示以下流程：

```text
选择目标学期与导入方式
→ 选择文件或课表图片
→ 预览识别结果并选择课程
→ 查看时间冲突并确认处理
→ 完成导入并查看课表
```

导入预览允许用户选择全部或部分课程；发现时间重叠时，原型提供查看课程和明确保留两门课程的选项，避免在未确认的情况下覆盖或丢弃安排。

### 2.7 灵活的任务记录规则

原型中的统一待办列表支持“按时间”和“按课程”两种组织方式，同时保留“未关联课程”和“无截止日期”的分组。因此，课程关联应为主要使用路径，也应容纳打印讲义、整理资料等暂时没有明确课程归属或截止日期的事项。

待办标题必填，截止日期和具体时间均可不填。仅填写日期时不自动补成 `00:00`；填写具体时间前需先选择日期。清除时间保留日期，清除日期则同时清除时间。这样的设计能区分“周五前完成”和“周五 16:00 前提交”，减少不必要的录入和错误的时间表达。

### 2.8 桌面小组件

原型展示九种桌面小组件方案，覆盖下一节课、今日课程、本周课表、即将到期待办、快速笔记、今日课毕、深色显示，以及时间待设置、时间冲突等状态。

小组件将课程名称、时间、地点和重要任务放在更容易查看的位置。设计说明约定点击课程进入课程详情、点击待办进入待办详情、点击笔记进入课程笔记，使查看信息与后续操作能够衔接。其预期价值是减少频繁打开应用查课的操作。

### 2.9 典型使用流程

以“教师在软件工程课上布置需求分析报告”为例，预期使用流程为：

1. 用户通过课表打开“软件工程”的课程快捷面板。
2. 点击“添加待办”，创建“完成需求分析报告”任务，按实际要求填写截止日期及可选的具体时间。
3. 在该课程下记录报告要求、提交方式等备忘内容。
4. 课后通过统一任务列表查看待办事项，再进入对应课程查阅相关记录。
5. 完成报告后更新任务状态，并保留课程记录以供后续查阅。

由此形成“查看课程—记录任务—查阅要求—完成任务”的连续流程。

## 3. B — Benefit：用户收益

ClassFlow 的预期价值在于减少学习信息的录入、记录、查找和维护成本，使用户更容易掌握每门课程的学习安排。导入、课程快捷面板、多视图和桌面小组件分别对应首次设置、课堂记录、学习规划和日常查看等环节。

### 3.1 减少记录与查找时间

课程快捷面板提供任务与笔记入口后，用户可以在已有课程信息的基础上继续记录，无需在每次记录时重新说明课程名称，也减少了在多个软件之间切换和搜索的步骤。桌面小组件则为查看下一节课的时间与地点提供了更直接的入口。

例如，用户查找“软件工程报告的截止时间和提交要求”时，可以在同一课程下查看相关任务与笔记，预期降低信息查找成本。

### 3.2 降低任务遗漏风险

统一任务列表有助于用户集中查看不同课程的作业、实验和考试准备事项，减少因记录位置分散而遗漏任务的可能。按时间分组、月视图中的到期待办和待办小组件，提供了多个可见的任务提示入口。

任务与课程关联后，用户不仅知道“需要完成什么”，还能够快速查阅“这是哪门课程的要求”。仅日期、日期加时间和无截止日期三种情况的区分，有助于准确表达任务要求。

### 3.3 减少整理负担，改善学习安排

课程、任务和笔记按照固定结构组织，有助于用户减少自行建立文件夹、标签和分类规则的工作。按课程分组便于查找，按时间分组便于安排先后次序。导入预览可减少逐门录入的工作，课节与时间视图则降低了自行换算上课时间的负担。

导入和作息修改中的冲突提示，有助于用户及时发现安排重叠。它提供的是核对与决策支持，冲突如何解决仍由用户决定。

### 3.4 保留跨学期的学习记录

通过学期管理，用户可以区分当前课程与历史课程，并在需要时查阅过去的课程笔记和任务记录。这有助于复习、后续课程学习以及回顾已有学习成果。

### 3.5 收益验证与使用成本

| 预期收益 | 验证指标 | 验证方式 |
| --- | --- | --- |
| 记录更便捷 | 从打开工具到保存一条课程任务的时间、操作步骤数 | 对同一记录任务进行对照测试 |
| 查找更高效 | 找到某门课程的任务截止时间与相关要求所需时间、查找成功率 | 设置一致的信息查找场景 |
| 首次录入更省力 | 建立完整课表的总耗时、导入后修正次数 | 将导入预览流程与逐门手动录入进行比较，包含修正时间 |
| 时间与课节更清晰 | 找到下一节课实际时间的成功率、作息修改后的安排准确性 | 测试已配置、未配置与存在冲突的场景 |
| 日常查看更直接 | 查到下一节课时间与地点的耗时、小组件使用反馈 | 比较应用内查看与小组件查看，并检验状态是否及时更新 |
| 任务更少遗漏 | 试用期间未记录或错过截止时间的任务数量 | 结合用户日记、访谈和自愿提供的任务记录核对 |
| 更容易持续使用 | 首次完成“建课—建任务—查笔记”的比例、7 日与 30 日留存率 | 在可运行版本中观察实际使用 |
| 学期管理更清晰 | 切换学期、找到历史课程的成功率 | 进行跨学期查找测试 |

记录时间的改善可按以下方式计算：

> 记录时间降低比例 =（原有工具平均记录时间 − ClassFlow 平均记录时间）÷ 原有工具平均记录时间 × 100%

## 4. C — Competitors：竞争分析

ClassFlow 的替代方案既包括单一工具，也包括学生已经形成的“课表 App + Todo + 备忘录 + 课程群聊”使用组合。竞争分析应比较用户完成同一学习任务的体验，而不只比较功能数量。

### 4.1 主要竞争对手与替代方案

| 类型与代表 | 已有优势 | ClassFlow 需要证明的价值 |
| --- | --- | --- |
| 以查看课程时间为主的课表工具 | 课程时间展示直接，符合日常查看课表的习惯 | 从课程进入任务与笔记是否更方便，且不会增加查课表的负担 |
| 通用任务管理工具，如 Todoist | 提供任务、项目、优先级、标签、日期和提醒等管理能力 | 默认提供课程与学期结构，是否能减少用户自行配置和维护的工作 |
| 通用笔记与工作空间工具，如 Notion | 能整合笔记、文档、项目和任务，组织方式灵活 | 面向大学课程的预设流程是否更容易上手、记录是否更快捷 |
| 学生学习规划工具，如 MyStudyLife | 已将课程、作业和考试纳入学习规划，并提供相关提醒 | 需要进一步比较课程笔记关联、学期组织和具体记录流程，而不能只依靠“功能整合”形成差异 |
| 多工具组合 | 用户已有使用习惯，各工具可以分别满足不同需求 | 集中管理带来的便利是否足以覆盖迁移成本，并保持常用操作的效率 |

竞品功能依据：Todoist 的任务、项目、标签与提醒能力见其[官方功能说明](https://www.todoist.com/task-management)；Notion 的笔记与任务整合能力见其[官方笔记产品说明](https://www.notion.com/notes?locale=en_US)；MyStudyLife 的课程、作业、考试与提醒能力见其[官方网站](https://mystudylife.com/)及[使用说明](https://care.mystudylife.com/en/articles/9502657-how-to-use-msl)。

### 4.2 差异化定位

根据当前方案，ClassFlow 可以将差异化定位集中在以下方面：

1. **以课程表作为学习信息入口**  
   用户查看课程后，可以继续处理该课程的任务与笔记，使查课表与记录学习事项形成连续流程。

2. **默认建立课程关联**  
   从课程页面创建任务或笔记时直接确定归属，减少用户额外建立分类规则的工作。

3. **同时支持课程视角与任务视角**  
   课程详情用于集中查阅一门课的相关内容，统一任务列表用于安排多门课的待办事项。

4. **以学期组织课程资料**  
   将学期作为上层管理单位，使当前学习安排与历史课程记录具有清晰边界。

5. **将课程记录与高校作息联系起来**  
   原型明确设计了课节与时间视图、按学期维护作息、时间未配置时的替代查看方式，以及作息修改的影响与冲突确认。这些细节可以作为面向高校课程场景的体验优势进行验证。

6. **覆盖首次录入与日常查看**  
   导入预览及冲突处理降低建课表的负担，桌面小组件降低日常查课和查看待办的成本，使产品价值覆盖整个使用过程。

### 4.3 核心壁垒与竞争风险

核心壁垒包括：通过持续的校园用户反馈改进课程使用流程；在基础课节与学期规则的基础上适配更多高校的实际安排；积累可靠的导入格式适配能力；在长期使用中保持记录准确、查找方便与数据可靠。

主要竞争风险：用户认为现有工具已经够用，或首次录入与迁移成本过高。因此，ClassFlow 应优先验证“记录一条课程任务”和“找到一门课的要求”这两类高频操作，确认它们能给用户带来可感知的改善。

## 5. D — Delivery：推广与交付

ClassFlow 的交付建议从校园小范围试用开始，先验证核心需求和操作体验，再根据反馈扩大推广。

### 5.1 首批用户与推广信息

首批用户可选择课程数量较多、作业与实验任务较频繁、目前使用多个软件管理学习事项的大学生。相比面向所有学生，这类用户更容易判断集中管理是否解决了实际问题。

推广时可围绕一个具体场景说明产品价值：

> 打开课表，就能找到这门课的作业和笔记。

演示内容应展示“教师布置任务—课程内记录—课后查阅—完成任务”的完整过程，使用户直接看到产品如何融入日常学习。

### 5.2 分阶段交付

**第一阶段：原型验证**

邀请约 10—15 名目标学生完成查看课表、从快捷面板创建课程任务、查找笔记、切换学期，以及核对导入结果等操作，记录操作阻碍和理解偏差。访谈重点应包括用户过去是否遇到相应问题、当前如何解决，以及是否愿意持续记录。还应检查用户能否理解课节与时间视图，以及“无截止日期”的任务规则。

**第二阶段：最小可用版本试用**

可以先交付课程与学期管理、课程快捷面板、课程关联任务、按时间与课程组织的待办列表、简单课程笔记和基本课节作息配置，完成核心使用流程。

邀请约 30—50 名学生在 2—4 周内使用实际课程数据进行试用，观察首次设置成本、日常记录频率、信息查找效率和任务遗漏情况。

**第三阶段：扩大校园推广**

在核心流程稳定、用户能够持续使用后，再扩大到更多班级或院系。可利用开学排课、期中任务集中和期末复习等场景，展示与当时需求直接相关的使用方法。

### 5.3 用户触达与反馈渠道

- **班级与课程群**：经群管理者同意发布试用说明和演示，邀请有明确需求的学生参与。
- **学生社团与校园体验活动**：通过现场演示收集首次使用反馈，观察用户能否独立完成核心操作。
- **校园社区与内容平台**：发布具体使用场景，例如“如何集中查看本周各门课的作业”，让用户理解使用价值。
- **同学推荐**：在早期用户认可体验后，鼓励其向有相似需求的同学推荐。

反馈应同时覆盖持续使用者与停止使用者，区分功能缺失、操作复杂、维护成本过高和需求不强等原因，避免仅凭下载量判断推广效果。

### 5.4 首次使用与正式交付要求

首次使用应帮助用户完成一个最小过程：创建当前学期，通过手动录入或导入预览添加课程，从课程快捷面板记录一个任务，并在课程相关记录与统一任务列表中找到同一任务。让用户尽早体验信息关联的价值，再引导其逐步完善课表。具体时间未设置时，应按原型设计保留课节查看方式。

正式交付前，建议确认以下要求：

- 课程、任务和笔记保存后能够再次正确读取，关联关系不会因切换页面而丢失。
- 当前学期与历史学期区分清楚，同名课程不会被错误合并。
- 仅截止日期的任务不自动变成午夜到期；无截止日期和未关联课程的事项能被正确保存与展示。
- 文件或图片导入结果可以核对，用户选择的课程与目标学期准确，保留冲突不会导致安排被静默覆盖。
- 按课节安排跟随本学期作息，自定时间安排不随课节修改；时间未配置时仍可查看课节安排。
- 若交付小组件，显示状态与应用数据一致，时间冲突、时间待设置等状态准确，点击可到达对应功能。
- 修改或删除课程时，相关任务与笔记的处理方式明确，避免用户误丢记录。
- 若交付提醒功能，应验证通知权限、时间设置和提醒可靠性。
- 提供基本的使用说明、问题反馈入口及数据导出或备份方式，降低长期使用顾虑。

### 5.5 商业化路径

初期可优先验证核心功能的使用价值，通过免费试用降低学生尝试成本。是否收费，应在确认持续使用需求、维护成本和付费意愿后决定。

可能的后续方向包括：

1. **个人增值服务**：在核心功能可用的基础上，探索跨设备同步、云端备份或高级学习统计等服务，并先调查用户需求与付费意愿。
2. **校园合作**：在产品稳定且具备对应能力后，探索与学生组织或高校开展试点合作，明确服务范围、维护责任与交付要求。

### 5.6 推广与交付效果评估

| 阶段 | 核心评估问题 | 建议指标 |
| --- | --- | --- |
| 触达 | 用户是否理解产品与自身学习需求的关系 | 演示后试用意愿、进入试用的人数 |
| 首次使用 | 用户是否体验到课程关联的价值 | 完成“建课—建任务—查记录”的比例、首次设置耗时 |
| 持续使用 | 产品是否进入日常学习流程 | 7 日与 30 日留存率、每周任务与笔记使用情况 |
| 实际收益 | 集中管理是否减少记录与查找成本 | 与原有工具相比的操作耗时、查找成功率和用户反馈 |
| 推广与维护 | 扩大使用规模是否可持续 | 获得一名持续使用者的投入、反馈处理量与维护成本 |

评估结果应回到最初的需求：学生是否更容易记录、找到并处理课程相关事项。只有当这些收益在真实学习场景中得到验证，扩大推广与商业化才有充分依据。
